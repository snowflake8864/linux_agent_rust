一、背景
═══════════════════════════════════════════════════════════════════════════════

服务器触发的 task_down_conf（TaskTypeEnum::TaskDownConf=6）路径：
  task_fetcher::run() → handle_task() → task_down_conf()
    → update_config_from_json()
      ├── 1. 克隆 old_cfg
      ├── 2. 从 JSON 更新字段到 new_cfg
      ├── 3. to_ini() 写入 net_info.ini
      └── 4. apply_config_diff(&old, &new) → 下发到内核

现有 gRPC 路径：
  ConfigService::UpdateConfig() → ConfigServiceImpl::update_config()
    → require_offline()?   ← 在线模式拒绝
    → data_hub.update_config()
      ├── 1. proto → JSON map
      ├── 2. 更新 NETINFO_CONFIG 字段
      └── 3. to_ini() 写入 net_info.ini
      ❌ 缺失 apply_config_diff！内核层不下发。


二、核心差距分析
═══════════════════════════════════════════════════════════════════════════════

apply_config_diff 负责的操作及 driver/ebpf 差异：

| 操作                        | driver 模式                  | eBPF 模式                      |
|-----------------------------|------------------------------|--------------------------------|
| self_protect_switch         | nl_sock.send_uint32(0x103)  | skip + warn（nl_sock 为 None） |
| open_port_switch            | write /proc/osec/net_rules  | SecurityBackend stub → Ok(())  |
| dynamic_switch              | write block_switch procfs   | SecurityBackend stub → Ok(())  |
| defense_switch (12 flag合成) | write /proc/osec/defense    | SecurityBackend stub → Ok(())  |
| proc_switch / syslog_process| nl_sock.send_message(0x702) | skip + warn（nl_sock 为 None） |
| file_switch 关              | pattern_mgr.clear_protect   | pattern_mgr（backend无关）     |
| extortion_protect 关        | pattern_mgr.clear_exiport   | pattern_mgr（backend无关）     |
| switch/protect→BPF maps     | 无（driver不需要）           | sync_switches → BPF maps  ★新增 |

★ 新增的安全后端方法 sync_switches()：
  - 定义在 SecurityBackend trait（common/src/backend.rs）
  - 默认空操作（driver模式不需要）
  - EbpfBackend 对接已有的 sync_runtime_switches() 方法
    → 写入 BPF maps: feature_switches + global_modes


三、方案设计
═══════════════════════════════════════════════════════════════════════════════

3.1 整体架构

                    ┌──────────────────────┐
                    │  pub fn apply_config_diff(old, new)   │  ← 独立函数
                    │  (crates/task/src/task_fetcher.rs)    │
                    └──────────┬───────────┘
                               │
              ┌────────────────┼────────────────┐
              │                │                │
         server路径        gRPC路径         直接调用
    (task_fetcher.rs)  (data_hub.rs)      (均可复用)

3.2 资源全局化
  两个 TaskFetcher 独占的资源通过 OnceLock 全局化：

  pub static GLOBAL_NL_SOCK: OnceLock<Mutex<Option<NlSockInfo>>> = OnceLock::new();
  pub static GLOBAL_PATTERN_MGR: OnceLock<Arc<Mutex<PatternRulesMgr>>> = OnceLock::new();

  在 TaskFetcher::new() 中注册，apply_config_diff 独立函数通过全局单例访问。

3.3 INI 开关设计
  [GRPC] 段新增字段：ALLOW_CONFIG_WRITE_ONLINE

  值=0（默认）：在线 gRPC 调用 UpdateConfig 返回 PERMISSION_DENIED
  值=1        ：在线 gRPC 调用 UpdateConfig 允许执行，完整下发

  开关在 NetInfoConfig 中的字段：grpc_allow_config_write_online: bool

五、行为矩阵
═══════════════════════════════════════════════════════════════════════════════

                          ALLOW_CONFIG_WRITE_ONLINE=0    ALLOW_CONFIG_WRITE_ONLINE=1
                          ──────────────────────────    ──────────────────────────
  在线模式 - 服务器路径   完整下发 ✅（不受影响）         完整下发 ✅（不受影响）
  在线模式 - gRPC 路径    PERMISSION_DENIED（旧行为）   完整下发 ✅（新增能力）
  离线模式 - 服务器路径   不可用（服务器不可达）          不可用（服务器不可达）
  离线模式 - gRPC 路径    完整下发 ✅（补齐了diff）      完整下发 ✅（补齐了diff）

  "完整下发" = ini 写入 + apply_config_diff → 内核/BPF


六、安全性考量
═══════════════════════════════════════════════════════════════════════════════

  (1) 默认值 0 = 安全保守，已部署系统升级后行为不变
  (2) 开关=1 时，在线模式下服务器下发和 gRPC 下发可能并发
      → NETINFO_CONFIG 的 Mutex 保证原子性
      → 最后写者胜出（last-write-wins）
      → 两者都是可信来源（服务器/本地管理员），竞态可接受
  (3) eBPF 模式下 nl_sock 为 None
      → SelfProtect、NetLogPolicy 操作被优雅跳过（log warn）
      → sync_switches() 正常写入 BPF maps
  (4) 其他 gRPC 写操作（task_local、ip_policy、protection_mode 等）
      不受此改动影响，仍由 require_offline() 统一管控

       - task_down_conf 功能完全不变

    4. Driver 模式:
       - cat /proc/osec/defense_switch → 反映 gRPC 修改

    5. eBPF 模式:
       - gRPC UpdateConfig 不报错（nl_sock skip）
       - BPF maps 正确更新（sync_switches）
